# 非真原型

原型的目的不是「能用」，是**能看出对不对**。

「非真」是硬约束，不是谦辞。它一眼就该看出是一次性的。任何让它更像正式实现的努力都是浪费：你验证完就会扔掉，而它长得越像真的，越容易留下来变成负债。

## 1. 先分清在回答哪个问题

选错介质就白做。

| 问题 | 介质 | 产出 |
| --- | --- | --- |
| 界面该长什么样 | 画板（draw2code）或线框 | 几屏，能指着说「这里不对」 |
| 状态／逻辑对不对 | 单文件 HTML，按钮手动驱动，状态全打印 | 点几下就能看见状态怎么变 |
| 数据形状够不够 | 一张表，或一段写死的 JSON | 能数清字段、看出缺哪个 |
| 流程顺不顺 | 画板上的箭头，每步一句话 | 能从头走一遍，指出卡住的地方 |

选介质只有一条原则：**能让你最快看见「不对」的那个**，不是最像成品的那个。

环境里有画码（draw2code）就用它：改一版的时间以秒计，而且天然不像成品。没有就用纸、ASCII 线框、一张表，不要为了「专业」先去搭框架。

## 2. 六条硬规则

1. **一眼假**：文件或目录叫 `sketch-*`，顶部写一句「一次性原型，不要留」。
2. **单文件**：双击能开。不安装、不构建、不配环境。
3. **内存态**：不落库、不接真接口。数据写死在文件里，刷新就重置。
4. **不抛光**：不写测试，不抽组件，错误处理只做到能跑。样式够看清就行。
5. **只做被问的那一件事**：顺手加的功能都是没验证过的假设，它们会偷走注意力。
6. **不进主干**：结论回 `PREDEV.md`，代码放 `sketch/` 或做完就删。

## 3. 逻辑档：把状态亮出来

每次操作后打印完整状态，而不是只描述「刚才发生了什么」。看不懂变化的原型等于没做。

```js
const state = { step: 'idle', items: [], error: null }
const log = []
function render() {
  document.querySelector('#state').textContent = JSON.stringify(state, null, 2)
  document.querySelector('#log').textContent = log.join('\n')
}
```

再给三组预设场景（正常、边界、失败），一键载入。否则你要手点二十次才能到出问题的地方。

## 4. 界面档：先定方向，再画

不要直接画。先填五个格子，每个一两行：

- **主题**：产品是什么、给谁、主要工作是什么。写不出就先回去问，别画。
- **色**：4–6 个命名值，每个写作用（底、面、主文字、次文字、强调、状态）。不写「大概蓝色」。
- **字体**：一到两族，写清各自角色。能用一族就一族。
- **布局**：一句话 + 一个 ASCII 框，标出内容怎么对齐。左对齐是默认答案，居中要有理由。
- **独特**：一句「什么让它只可能是这个产品」。写不出这句，方向就还没定。

画的时候默认避开这三个痕迹，它们与题材无关地出现在任何页面上：

- 只给标题里一个词加斜体或换色当强调。
- 全大写的小标签当分区标题。
- 内容上方多余的一行引导小字。

画完自查：把全部文案换成别的产品的文案，如果这屏还能用，说明方向没做选择，回去改方向，不要改细节。

方法是 frontend-design 那套：视觉选择来自题材本身，不是来自好看的模板。只在一处用力——一个元素当记忆点，周围全部安静规整；画完回头看一遍，删掉一个装饰。

## 5. 收手

问题被回答了就停。

- 结论带回 `PREDEV.md`：改一条决定，或补一条假设。
- 原型本身留在 `sketch/` 或者删掉，不要合并进正式代码。

原型长得太快，通常说明当初那个问题不需要原型，只需要一个决定。这时候停下来说这句话，比继续做更有价值。

**不要让原型变成项目。** 它一旦开始需要「重构」，你已经在写正式实现了——那就正式立项，或者扔掉重来。
