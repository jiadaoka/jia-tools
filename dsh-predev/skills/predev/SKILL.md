# 开发之前

只做一件事：把一个模糊想法谈成一份能开工的约定。

它防两个坑，同一个人会轮流掉进去：

- **过度松懈**：直接开写，写到一半发现方向没想清，推倒重来。
- **过度设计**：动第一行代码之前就想把设计想完美，想两周，一行没写，然后没兴趣了。

第二种更常见，所以第一原则不是「想清楚一切」，是**够开工**。这两件事完全不同，混为一谈正是这个技能要防的失败。

## 1. 先定投入档位

问任何「做什么」之前，先问一句：**这东西你打算投多少？**

不问档位就往下问，是这类访谈最常见的死法：一个周末玩具被问了三十个问题，问到用户不想做了。

| 档位 | 判据 | 预算 | 产出 |
| --- | --- | --- | --- |
| 玩具 | 只有你用；坏了不心疼；目标是跑起来看看 | ≤ 5 问，1 轮 | 五条地板，立刻开工 |
| 小工具 | 你会长期用，或者几个人会用 | ≤ 15 问，2–3 轮 | 五条地板 + `PREDEV.md` |
| 项目 | 别人会用；要维护一年以上 | 不设上限 | `PREDEV.md` |

拿不准就**建议往下选一档**。选低了随时能升；选高了，烧掉的是自己开工的意愿。

## 2. 什么不该问

每当一个问题的答案需要「看看才知道」，它就不该以问题的形式存在：

- **长什么样、手感如何、状态怎么流转** → 不要讨论。写一个非真原型看，加载 `predev-sketch`。
- **「我得先查一下 X」** → 查得到就是**你**的活，不是用户的决定。查完再问，不要排进队列。
- **可逆、代价又低** → 不问。取合理默认值往前走，记进「默认值」，让用户事后否掉。

## 3. 过筛：改主意的代价

只有一条标准：

| 代价 | 处理 |
| --- | --- |
| 几分钟 | 不问，取默认值，记一行 |
| 几天 | 问，进队列 |
| 要重写 | 问，而且放最前面 |

## 4. 轮次与前沿

**前沿**是前置条件已经定下来的决定：现在就能问、不用赌还没听到的答案。一轮里把整个前沿问掉，然后**停下来等回答**。

```
❓ **Q1** - **<标题>**：<问题，可多段，可带选项>

➡️ <推荐答案，一句话说清理由>

---

❓ **Q2** - **<标题>**：<问题>

➡️ <推荐答案>
```

三个纪律：

- 一个答案依赖同一轮里另一个没答的问题，它属于更靠后的轮次。
- 用「建议」而不是「你看呢」。给了推荐答案，用户才有东西可以否。
- 一次问完就地停下。等回答，不要自问自答往下推。

查**事实**永远是你的活：读文件、搜网、派子代理。正在跑的事实查询算一个未定的前置，它下游的问题要等，前沿里其余的现在就问。

**决定才是用户的**：逐条摆出来，然后等。

## 5. 停止线：五条地板

档位再低，这五条也不能空。缺哪条，都会在写代码时反复返工。

1. **一句话**：这东西是干嘛的、给谁用。
2. **收手线**：怎样算做完，或者什么情况下可以停。必须可判定。
3. **怎么跑起来**：技术栈，加一条能启动它的命令。
4. **第一个切片**：第一个端到端跑通、看得见的最小东西。
5. **不做**：这次明确不做什么。

满足**任一**条件就停：前沿空了，或者五条地板齐了且预算用完。

不要为了「想完整」继续问。剩下的每一条都推迟到写代码时再定：那时有真实信息，做决定更容易、更准、成本更低。

用户随时可以喊停。自然语言是控制手段，不是问题计数器。

## 6. 写下来

停下来之后必做两件事：复述一遍确认是同一件事，然后写进项目根的 `PREDEV.md`。

只在对话里达成的共识不算共识：对话会被压缩、会被下次会话遗忘，文件不会。

```markdown
# <项目名>

## 一句话
## 收手线
## 怎么跑起来
## 第一个切片
## 不做
## 已定的决定        <!-- 表格：决定 / 为什么 / 日期 -->
## 默认值（可推翻）   <!-- 表格：项 / 取了什么 / 改起来的代价 -->
## 待验证假设        <!-- 表格：假设 / 怎么验证 / 状态 -->
## 变更记录
```

写这个文件时只有三条硬规则：

1. **只写两种句子**：已定的决定（一句能被反驳的话）和待验证假设（写清怎么验证）。把假设混进决定里，是最常见的自欺。
2. **收手线必须可判定。**「好用」不可判定，「导出一个 .md 含标题、UP 主、链接」可判定。
3. **「不做」必须非空。** 空着说明还没砍东西，而没砍过的范围一定偏大。

不写实现细节（文件路径、库版本），它们很快过期，而且多数不是决定。

写完给用户过一遍，只问三件事：哪里写错了？哪条其实是假设？缺了什么？

之后决定变了就先改文件再改代码，并在「变更记录」加一行。这个文件写完就可以不再动，除非决定变了。
