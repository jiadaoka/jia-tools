# dsh-predev

> 开发之前：把想法问到够开工，写成 `PREDEV.md`，需要看效果时做非真原型。

## 安装

在 `jia-tools` 根目录执行：

```sh
dsh plugin --profile desktop add .\dsh-predev
```

重启 profile 后生效。卸载：

```sh
dsh plugin --profile desktop remove dsh-predev
```

## 技能

### predev

讨论，然后约定。先问「这东西你打算投多少」，按投入档位给提问预算（玩具 ≤5 问，小工具 ≤15 问，项目不设上限），然后按轮推进：一轮把整个前沿问完，停下等回答。

每个问题都带推荐答案——用「建议」而不是「你看呢」，你才有东西可以否。查事实是它的活，决定才是你的。停下来时把五条地板补满：一句话、收手线、怎么跑起来、第一个切片、不做什么，然后写进项目根的 `PREDEV.md`。

那里只有两种句子：已定的决定（一句能被反驳的话）和待验证假设（写清怎么验证）。把假设混进决定里是最常见的自欺。

### predev-sketch

非真原型，回答一个「得看看才知道」的问题。先分清是哪种问题：界面该长什么样、状态对不对、数据形状够不够、流程顺不顺——四种问题四种介质，画板、单文件 HTML、一张表、箭头图。

选中介质的标准只有一条：能让你最快看见「不对」的那个，不是最像成品的那个。「非真」是硬约束：一眼假、单文件、内存态、不抛光、只做被问的那一件事、不进主干。界面档要先填五个格子（主题、4–6 个命名色值、字体角色、布局一句话、一句「什么让它只可能是这个产品」）再动手。

问题被回答了就停，结论回 `PREDEV.md`。

### predev-wait

一句话技能。上一条没听懂时用：要求先给背景、用短句、一句话只说一件事、专业名词先解释或者别用，且不要复述整段历史。模型不会自动调用它，只认你手打。

## 它防的是什么

同一个人会轮流掉进两个坑：

- **过度松懈**：直接开写，写到一半发现方向没想清，推倒重来。
- **过度设计**：动第一行代码之前就想把设计想完美，想两周，一行没写，然后没兴趣了。

第二个坑更常见。所以第一原则不是「想清楚一切」，是**够开工**。这两种结果的差别，决定了问多少问题、在哪停。

## 一次访谈

第一步永远先问投入档位。不问就往下问，是这类技能最常见的死法：一个周末玩具被问三十个问题，问到你想放弃为止。

| 档位 | 判据 | 预算 |
| --- | --- | --- |
| 玩具 | 只有你用，坏了不心疼 | ≤ 5 问，1 轮 |
| 小工具 | 你会长期用，或几个人用 | ≤ 15 问，2–3 轮 |
| 项目 | 别人会用，要维护一年以上 | 不设上限 |

假设是玩具，一轮把整个**前沿**问完：

```
❓ Q1 - 收手线：导出到什么程度算做完？
➡️ 建议：一个收藏夹产出 .md，含标题、UP 主、链接、收藏时间。不做分页。

❓ Q2 - 怎么跑起来：命令行还是网页？
➡️ 建议：单文件脚本。你自己用，不需要网页。

❓ Q3 - 数据从哪来：官方 API 还是抓页面？
➡️ 建议：我去查，不占用你的决定。

❓ Q4 - 不做：这次明确不做什么？
➡️ 建议：不做登录态管理、不做图片下载、不做批量。
```

三件事值得注意：

- **Q3 不是问题。** 查事实永远是插件的活，只有**决定**才排进队列。
- 一轮问完就停。你的回答会解锁下一轮。
- **五条地板齐了就停**，哪怕前沿还没空。剩下的推迟到写代码时再定。

过筛只有一条标准，**改主意的代价**：几分钟就取默认值不问，几天就进队列，要重写就排最前面。

## 非真原型

「非真」是硬约束。原型的目的不是能用，是**能看出对不对**。它一眼就该看出是一次性的：单文件、内存态、不接真数据、不抽组件、不进主干。

先分清在回答哪个问题，再选介质：

| 问题 | 介质 |
| --- | --- |
| 界面该长什么样 | 画板（draw2code）或线框 |
| 状态／逻辑对不对 | 单文件 HTML，按钮驱动，状态全打印 |
| 数据形状够不够 | 一张表，或一段写死的 JSON |
| 流程顺不顺 | 画板上的箭头，每步一句话 |

界面档不直接画。先填五个格子——主题、4–6 个命名色值、一到两族字体、布局一句话、一句「什么让它只可能是这个产品」——再画，画完换掉全部文案自查一遍。视觉选择来自题材本身，不是来自好看的模板；只在一处用力，其余安静规整。

## 结构

```
dsh-predev/
  index.js              # 插件本体：读 skills/*/SKILL.md，注册进 ctx.skills
  cordis.patch.yml      # bundle 补丁层，按包名引用插件
  package.json          # dsh.bundle manifest
  skills/
    predev/SKILL.md         # 档位、过筛、前沿、五条地板、停止线、PREDEV.md 结构
    predev-sketch/SKILL.md  # 四档介质、六条硬规则、界面方向
    predev-wait/SKILL.md
  scripts/check.mjs     # 自检
```

没有 `templates/`、没有 `references/`：技能正文自足，模板就是 `predev` 里那段结构，界面检查表就在 `predev-sketch` 里。多一个文件就多一条会断的路径。

改技能就是改 `skills/` 下的 Markdown，重启生效。改完跑自检：

```sh
node scripts/check.mjs
```

它用桩 `ctx.skills` 跑一遍 `apply()`，检查三个技能都在、名字和目录一致、调用策略正确、frontmatter 合法、技能之间的引用没有断。
