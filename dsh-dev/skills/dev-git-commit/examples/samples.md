# 样例 Commit 信息

> 共同约定：
> - **subject 写"业务目标"或"解决的业务问题"**，不是"改动清单"（不是"导入流程拆 3 步 + 复选框锁定 + 搜索清空"这种多改动并列表述）
> - 单个改动点 → 无 body，subject 一行
> - 多改动点 → 必须 body，**有序列表**（`1.` `2.` `3.`），每项写**业务能力**（"为什么做、提供了什么"），不写具体实现细节、不加括号
> - 具体细节（数字、参数、按钮文字、文件名、字段名）一律不进 subject / body
> - footer 由用户在主体确认后主动提供（工单 URL、issue 引用、评审点等），草稿阶段不自动写

## 1. feat — 新增功能（多改动点，聚合）

**触发场景**：识别出多个改动点（新增接口 + 完善兜底），用户选 A 策略"聚合为一个 commit"。

```
feat(api): 新增用户画像查询接口

1. 提供用户画像数据查询能力
2. 完善空数据场景下的前端兜底支持
```

> 此处 footer 由用户后续提供，例如 `Refs #128`。

## 2. fix — 修复 bug（多改动点，聚合）

**触发场景**：根因是时区处理，同时需要补测试覆盖。

```
fix(auth): 修复跨时区用户登录后立即失效

1. 调整登录态有效期的时区处理
2. 补充时区相关测试覆盖
```

## 3. docs — 仅文档（单改动点，无 body）

**触发场景**：只改 `README.md`。

```
docs: 补充本地开发环境启动步骤
```

## 4. refactor — 重构（多改动点，聚合）

**触发场景**：抽离组件状态 + 缩减组件体积（多件事但同一目标）。

```
refactor(auth): 抽离登录组件状态管理

1. 提升登录组件的可读性与可测试性
2. 收敛表单状态的复用入口
```

## 5. perf — 性能优化（单改动点，无 body）

**触发场景**：仅在列表组件加缓存。

```
perf(user-list): 缓存列表排序结果减少重渲染
```

> 单改动点、subject 已经把"做了什么 + 目的"讲清楚 → 无 body。

## 6. Breaking change（多改动点，聚合）

**触发场景**：移除旧版接口 + 涉及调用方迁移说明。

```
feat(api)!: 移除旧版用户接口

1. 下线旧版用户接口
2. 推动调用方迁移到新版本
```

footer 由用户主动提供（迁移说明、issue 关闭等）：

```
BREAKING CHANGE: 调用方需切换到新版本接口；返回结构存在字段差异，详见迁移指南。
Closes #512
```

## 7. chore / build / ci（单改动点，无 body）

```
chore(deps): 升级开发依赖到最新次版本
```

```
build: 切换前端打包器到 vite
```

```
ci: 在合并流水线加入代码风格检查阶段
```

## 8. 极小改动（单改动点，无 body）

```
fix: 修复首页按钮点击穿透
style: 统一代码格式化风格
```

## 反例（不要这么写）

```
❌ feat: 新增了用户登录接口。
❌ fix: 修复一些 bug
❌ Feat(auth): new login
❌ feat(src/components/auth/LoginForm.tsx): 改样式
❌ feat: 改样式
❌ refactor(auth): 抽离 LoginForm 内部状态到 useLoginForm
   - 新增 src/auth/useLoginForm.ts
   - LoginForm.tsx 行数从 280 减至 130
❌ fix(auth): 修复登录态提前过期
   - 之前用本地时区计算登录态有效期
   - 统一以 UTC 计算 expiresAt
   - 包含 lastActiveAt、preferences 字段
```

反例的共性问题：

- **不规范的 type / 大小写 / 中英混杂**
- **subject 加句号、加「了」、写成"修复一些 bug"式空话**
- **scope 写成完整文件路径**
- **type 选错**（"改样式"用 `feat` 而不是 `style`）
- **subject 写成"改动清单"**（多个动作并列，而非统一的业务目标）
- **body 写成"怎么做"**（列具体步骤、按钮文字、数字、文件路径、字段名、函数名）
- **body 加括号**（括号里的内容通常是冗余的"实现细节"）
- **body 引用代码符号当业务描述**（`useLoginForm`、`expiresAt` 是标识符，不是业务能力）

## 真实使用反例 → 正例

下面是真实项目中使用时的反例与对应正例，便于对齐"业务目标"风格。

### ❌ 反例（多个改动并列 + body 含具体实现 + 括号）

```
feat(dataIdentifierConfig): 导入流程拆 3 步 + 复选框锁定 + 搜索清空

1. 抽屉规格固定 1000px，禁用遮罩点击与 ESC 关闭
2. 流程拆为 3 步（选择文件 / 数据校验 / 数据导入），新增文件级校验步骤；阶段 A 失败按钮"上一步"改为"重新选择"统一回退到步骤 1
3. 跨页全选时锁定复选框（提供可配置开关）
4. 搜索/筛选条件变化时清空所有勾选（含行勾选与跨页全选）
5. 重复项处理组件加表单真实校验，移除冗余依赖
```

问题：
- subject "导入流程拆 3 步 + 复选框锁定 + 搜索清空"——多个动作并列，不是统一业务目标
- body 各项含具体数字（1000px）、具体禁用项（遮罩 / ESC）、具体按钮文字（上一步 / 重新选择）、具体步骤（选择文件 / 数据校验 / 数据导入）、括号

### ✅ 正例（业务目标 + 业务能力）

```
feat(dataIdentifierConfig): 优化数据标识页面导入流程与勾选交互

1. 规范导入抽屉的展示与关闭行为
2. 提供分步引导式导入流程
3. 保护跨页全选场景下的勾选状态
4. 联动搜索条件与勾选状态
5. 强化重复项处理表单的校验
```

要点：
- subject 写统一的业务目标（"优化 XX 流程与 XX 交互"）
- body 各项写业务能力（"规范 XX 行为"、"提供 XX 流程"、"保护 XX 状态"、"联动 XX"、"强化 XX"）
- 没有数字、按钮文字、具体步骤、括号

## 多改动点时的对话流程示例

```
用户：帮我写个 commit 信息
助手：检测到 3 个独立改动点：
  ① 新增 /users/:id/profile 接口
  ② 修复跨时区登录失效
  ③ 升级依赖到最新次版本
  怎么处理？
用户：聚合到 1 个 commit，主体用第 ② 个最重要
助手：好的，subject 写"修复跨时区登录失效"，其余改动进 body：
（输出 commit 信息草稿 + 询问 footer）
用户：footer 加一条 redmine 工单：http://redmine.example.com/issues/789
助手：好的，已加到 footer。最终 commit 信息：
（输出最终 commit 信息）
```
