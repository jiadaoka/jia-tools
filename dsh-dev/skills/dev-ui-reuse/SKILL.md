# 组件优先

**判据不是"哪个库里有"，是"这个需求属于哪一类"。**

1. 项目已引入的组件库里有对应实现，就用它。
2. 项目自己的共享层（组件、布局；具体叫什么、放在哪，以那个项目的既有约定为准）已有同类实现，就用它。
3. 两边都没有，才手写。手写的那个要落进共享层，不许在业务页面里就地长出来。

**用组件不等于放弃视觉控制。** 定制只走组件库给出的入口：主题变量、design token、组件暴露的插槽与部件、局部 `:deep()` 微调。不改内部结构选择器，改了就等它升版碎掉。

**反面教材**（来自真实项目）：把导航手写成 `div` 加自己算 active 类，等于把现成的菜单组件重做了一遍。凡是"自己算高亮、自己拼状态"的地方，先回去看组件库有没有对应的受控属性。

**唯一必须自己算的情况**：组件按精确键匹配高亮（拿 `index` 去比对），此时业务状态要映射成组件要的那个键。
