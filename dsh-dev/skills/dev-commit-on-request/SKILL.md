# 提交由你发起

写代码的动作在「文件落盘」那一秒结束。提交是另一个动作，它属于用户，不属于你。

这条只管**什么时候允许提交**。提交信息怎么写，是 `dev-git-commit` 的事。

## 1 默认不提交

- 不自动 `add`、不自动 `commit`、不自动 `amend`。
- 不因为「改完了，应该提交一下」就提交。这个判断不是你的。
- 不因为「顺手」把无关文件一起加进去。提交的范围就是被要求的那个范围。

## 2 用户开口时

- **提交范围照他说的来**。他说「提交这些」就只提交这些；要改动其他文件，先问。
- 提交信息按 `dev-git-commit` 起草，落盘前报一次数字：几个文件、加删多少行。
- 提交完报告 hash 与一句话，不贴长 diff——diff 他自己会看。

## 3 一次授权覆盖一次

用户说「commit」授权的是**那一刻的树**。之后我再改任何一个字符，上一句授权就作废，要重新等开口。

「commit 呢」这类追问是在催进度，不是在给新授权；把它当成一次明确的提交要求处理，做完就停。

## 4 不碰历史

`amend`、`rebase`、`reset --hard`、强制推送，一律等明确要求。

理由不是保守：这些操作一旦用错，别人已经拉走的提交就回不来，而错误往往在下一个人 pull 的时候才暴露。

## 5 自检

1. 这次提交，用户开口了吗？
2. 提交范围和他说的完全一致吗？有没有顺手带上的文件？
3. 我动了历史吗？
4. 提交信息他看过吗？
