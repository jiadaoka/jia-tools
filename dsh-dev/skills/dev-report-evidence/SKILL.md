# 交付要能被核对

交付不是「我做完了」，是「你可以自己验证」。这两者的差别，几乎全部体现在你怎么写交付说明。

## 1 `TODO:` 的语义

它的意思是「这里有意留白，原因与后续动作已登记」。它**不是**「以后再说」的垃圾桶。

- 不借 `TODO:` 加兜底分支（比如权限码没批下来就先放开）。
- 不借它加额外调用，不借它跳过校验。
- 真正的中间态必须写清：现在是什么、终态是什么、谁来收尾、什么时候必须收尾。

## 2 结构变更同步断言

- 改数据结构、接口签名、序列化格式时，**同一次改动内**同步更新结构断言与测试。
- 只改实现不改断言，测试会静默通过——它校验的还是旧结构，等于没有测试。
- 新增分支要同步补用例；删除分支要同步删用例，不留永远不执行的死测试。

## 3 汇报

- 给**命令与结果**，不给形容词。「跑过了」不算；「`<命令>` 通过，N 个用例，耗时 X」才算。
- 未验证的项如实标注「未验证」，并说明为什么没验证（环境缺失、依赖不可用、需要真机）。
- 不把「应该可以」「理论上没问题」写成结论。
- 交付前列出自查项与勾选结果；有未勾选项，视为未完成。

## 4 自检

1. 有没有用 `TODO:` 掩盖一个本该现在解决的问题？
2. 改了结构，断言同步了吗？
3. 汇报里哪些是验证过的，哪些是推断的？
4. 有没有一项是我说「应该没问题」的？
