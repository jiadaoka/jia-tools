# dsh-dev

> 开发时的纪律。三层载体：按项目身份装配的条款、每轮常驻的 6 条、两个门禁。

## 安装

在 `jia-tools` 根目录执行：

```sh
dsh plugin --profile desktop add .\dsh-dev
```

重启 profile 后生效。卸载：

```sh
dsh plugin --profile desktop remove dsh-dev
```

改条款不用重装：插件监听 `skills/`，文件变了自动重新收集。

## 规则

18 条，一条一个目录，按领域排列。

### dev-source-first

规范优先。已有代码只说明历史长，不说明合规；新增与修改按书面规范写，规范没覆盖时跟随目标文件现有写法并标 `TODO:`。服务之间写法不同时，分「契约差异」（别人依赖它，跟）和「违规差异」（规范禁止它，不跟）。它排在最前：如果存量即规范，其他条款都只是建议。

### dev-branch-discipline

分支模型。只在 `feature/*` 和 `hotfix/*` 上改代码，主干与发布分支只读；发布分支创建即冻结；修复类改动必须双合主干与开发线，只合一处会让下次发版把已修的缺陷带回来；禁止强推回并；分支名带单号。

### dev-change-request

变更请求与发版。标题写清做了什么，描述含背景、方案、影响面、验证方式，关联单号，破坏性变更显式声明。版本号在发布分支确定，标签打在主干且与发布分支一致，发布说明从提交与变更请求聚合，不靠人工回忆。

### dev-git-commit

提交信息起草。按 Conventional Commits 生成中文草稿，优先分析已暂存内容（staged 与 unstaged 不合并），只输出文本。它和门禁是一条线的两端：门禁拦住 `git commit`，它负责把该跑的命令写给你。

### dev-no-fabrication

不凭想象补全。不编接口路径、字段名、配置项、库用法；字段类型以契约为准，不按名字推断；版本与可用能力读实际安装的依赖，不凭记忆。核心判据是「这句话有出处吗」，给不出出处就不要写。

### dev-contract-untouched

既有契约未经确认不改。路径、字段名、枚举、返回结构、错误码、默认行为都算契约，判断标准是「改了它，会不会有人必须跟着改」。改之前先列影响面，能加字段就不改字段，调用方在同一次改动里同步完。

### dev-dependency-discipline

依赖纪律。引入新依赖前先查现有依赖与标准库；新依赖要说清解决什么、为什么现有不行、维护状态是否可接受。有已知高危漏洞且无修复版本时上报。不为绕过构建问题降级依赖、加 `--force`、改锁文件。

### dev-report-evidence

交付要能被核对。`TODO:` 的语义是「有意留白且已登记」，不是垃圾桶，不借它加兜底或跳过校验；改结构、签名、序列化格式时在同一次改动里更新断言，否则测试校验的还是旧结构；汇报给命令与结果，不给形容词。

### dev-file-safety

改文件安全。先完整读取，读不全就停手；默认精确替换，只有全新文件才整文件写入；改完自查 diff。目标是两件事：不覆盖别人的手工改动，不制造无关 diff。

### dev-comment-discipline

注释纪律。判断标准只有一句：注释里说的东西，在当前代码里还存在吗？不存在就删。不写无信息注释，公共方法只描述自身契约、不绑定具体业务。

### dev-auth-layers

认证与授权的分层。认证回答「你是谁」，请求级授权回答「能不能调这个操作」，展示级授权回答「要不要看到这个入口」。两套授权不可互换：用展示级替请求级是只藏不拦，用请求级做展示级会恒假、对全员隐藏。客户端显隐不是安全边界。

### dev-permission-granularity

权限点的粒度与中间态。一个业务对象一个权限点，不按接口数量裂变；新权限点必须登记归属、角色与默认值。权限没定稿时可以交付，但要留锚点定终态，不删判断、不拿另一类标识顶替、不静默上线。

### dev-ui-reuse

组件优先。判据不是「哪个库里有」，是「这个需求属于哪一类」：项目已引入的组件库有就用，共享层有就用，都没有才手写，而手写的那个要落进共享层。定制只走组件库给出的入口（主题变量、token、插槽），不改内部结构选择器。

### dev-ui-page-layout

布局默认起点。上中下三段，头尾可选、主体滚动；骨架在公共样式里铺一次，页面只负责用类名。声明了 `scope: always`，任何有界面的项目都适用。

### dev-vue-container-split

容器与业务分离。业务组件和容器是两个文件、同一个目录，对外只有容器一个入口；业务组件按它实际是什么命名，不叫 `Content`、`Body`、`Wrapper`。只在 Vue 项目里出现。

### dev-vue-sfc-order

单文件组件三段顺序。`template` 在最上、`script` 居中、`style` 在最后。只改注释或一行文案时不适用。只在 Vue 项目里出现。

### dev-verify-on-request

验证由你发起。代码落盘就是终点，构建、打包、跑测试、起 dev server 一律等你开口；写完把待跑命令和各自会产出什么列清楚交回去。只允许不产生副作用的纸面检查。

### dev-init-project

项目初始化。唯一一个会往项目里写文件的条款，也是唯一关掉模型自动调用的：只有你手打 `/dev-init-project` 才跑。它是一次性动作，不是持续约束，把「每个项目都要有、每次都得重写一遍」的基础件按项目自己的结构放好。

## 三层怎么分

| 层 | 载体 | 放什么 | 缺了会怎样 |
| --- | --- | --- | --- |
| 按需 | `skills/` | 有判断空间的条款 | 没人记得去查 |
| 常驻 | `prompt.md` | 最易违反、一句话能说清 | 记不住细节 |
| 门禁 | `tools.guard` | 二值判定：拦 / 放 | 只会拦，不解释为什么 |

分配判据三条：能不能机械判定、违反代价多大、值不值得每轮占上下文。门禁只有「拦」「放」两态，没有「提示」态——凡是要「提醒一下」的，做出来一定变成误拦。

## 条款怎么出现

插件不把条款一股脑注册进去。它注册一个 provider，DSH 每次收集 catalog 时会把当前工作目录传进来，插件据此算身份、挑条款：

```
provider.list({ cwd }) ──► 指纹 ──► 可见性 ──► 当前项目的条款清单
```

身份从标记文件推出来，多源任一命中：`package.json` 的依赖、`go.mod`、`pyproject.toml`、`pom.xml`、`.git/config` 里的远端。

- **栈**：`dev-vue-sfc-order` 只在 vue 项目出现。第二个词必须落在栈表里才算栈条款，`dev-git-commit` 的第二个词不在表里，所以它是通用的。
- **仓库**：`metadata.repo` 声明范围。用声明而不是前缀，是因为仓库名常含连字符，前缀在第一个 `-` 处就有歧义。
- **认不出身份 → 全部可见**。藏起来的代价大于多给的代价：多给几条最多是噪声，被藏起来是静默失效。

新增条款只要守住命名或写一行声明，可见性自动正确，不改代码。

## 门禁

只认两个判据，都是二值的：

- **版本控制写操作**：`git commit` / `push` / `reset` / `checkout` / `branch -D` 这类。拦的是 AI 的自动化行为，不是人的操作自由。
- **敏感路径写入**：`.env`、`*.pem`、`*.key`、`secrets.*`、`credentials.*`；`*.example` / `*.sample` 放行。

只看真正会被执行的片段：按 `&&`、`;`、换行切段，每段第一个词必须是 `git`，所以 `echo "git commit"` 和 `git log --grep=commit` 都不误拦。异常一律放行。

总开关：环境变量 `DSH_DEV_GUARD=off`，重启生效。

## 草稿区

撤下 ≠ 删除。`draft/` 里每份写四行：状态、来源、缺什么、取回条件。取回走三步：重写 → 注册（建回 `skills/<名字>/`）→ 测试。草稿可读、可讨论、可改，不可引用。

## 结构

| 文件 | 性质 | 干什么 |
| --- | --- | --- |
| `src/kernel.js` | 纯函数 | 命令判定、敏感路径、门禁裁定 |
| `src/fingerprint.js` | 纯函数 + 一次读取 | 从文件快照推导身份 |
| `src/assembly.js` | 纯函数 | 声明范围与身份的求交 |
| `src/catalog.js` | 读目录 | 扫描 `skills/`，解析 frontmatter |
| `index.js` | 唯一有副作用的地方 | 装配：provider + 常驻段 + 门禁 |

规则会频繁改，装配很少改。混在一起的结果是每改一条规则都要跑一遍端到端。

## 测试

```sh
node --test
```

41 个断言，三类：内核（11 个命令用例、7 个放行/拒绝用例、坏输入不抛错）、装配（纯函数可见性 + 真实挂载后两个临时项目返回不同条款）、结构（目录名与 name 一致、description 长度与路由判据、引用的补充文件存在、草稿区无生效形态文件、常驻 4–6 条、公共条款无本机地址与内网 IP）。

## 这个版本没做的

- **跨目录的激活状态累积**。`provider.list()` 只拿得到 `cwd`，拿不到会话标识，所以得到的是「当前目录的视角」，多个仓库同时动时切走会收走前一套。
- **门禁没有分支判据**。判断当前分支要在每次工具调用里同步读仓库状态，而 `guard` 拿不到 `cwd`。拦掉 `commit` / `push` 覆盖了它想防的后果。
- **仓库事实类条款为空**。机制支持 `metadata.repo`，但还没有真实的仓库条款进来。
