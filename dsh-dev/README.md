# dsh-dev

> 开发时的纪律。三层载体：按项目身份装配的条款、每轮常驻的 6 条、两个门禁。

## 安装

在 `jia-tools` 根目录执行：

```sh
dsh plugin --profile desktop add .\dsh-dev
```

重启 profile 后生效。卸载：

```sh
dsh plugin --profile desktop remove dsh-dev
```

改条款不用重装：插件监听 `skills/`，文件变了自动重新收集。

## 规则

14 条，一条一个目录，按领域排列。每条只判一件事；同一件事不写在两处。

### dev-source-first

规范优先。已有代码只说明历史长，不说明合规；新增与修改按书面规范写，规范没覆盖时跟随目标文件现有写法并标 `TODO:`。服务之间写法不同时，先分清是「契约差异」（别人依赖它，跟）还是「违规差异」（规范禁止它，不跟）。

### dev-no-fabrication

不凭想象补全。不编接口路径、字段名、配置项、库用法；字段类型以契约为准，不按名字推断；版本与可用能力读实际安装的依赖。判据是「这句话有出处吗」，给不出出处就不要写。

### dev-contract-untouched

既有契约未经确认不改。路径、字段名、枚举、返回结构、错误码、默认行为都算契约，判断标准是「改了它，会不会有人必须跟着改」。改之前先列影响面，能加字段就不改字段，调用方在同一次改动里同步完。

### dev-dependency-discipline

依赖纪律。引入新依赖前先查现有依赖与标准库；新依赖要说清解决什么、为什么现有不行、维护状态是否可接受。有已知高危漏洞且无修复版本时上报。不为绕过构建问题降级依赖、加 `--force`、改锁文件。

### dev-commit-on-request

提交由你发起。没开口就不 add、不 commit、不 amend；一次授权只覆盖那一刻的树，之后改动任何字符都要重新等。`amend`、`rebase`、`reset --hard`、强推一律等明确要求。只管「什么时候允许提交」，怎么写是 `dev-git-commit` 的事。

### dev-git-commit

提交信息起草。按 Conventional Commits 生成中文草稿，优先分析已暂存内容（staged 与 unstaged 不合并），只输出文本。多改动点时先问聚合策略，subject 写业务目标而不是改动清单。

### dev-verify-on-request

验证由你发起。不构建、不打包、不跑测试、不起服务，三类禁令没有例外，全等你开口；写完把待跑命令和各自会产出什么列清楚交回去。纸面检查（读文件、diff、grep、核对签名）不受限。这三类现在也在门禁里。

### dev-file-safety

改文件安全。先完整读取，读不全就停手；默认精确替换，只有全新文件才整文件写入；改完自查 diff。改结构、签名、序列化格式时，在同一次改动里更新断言——只改实现不改断言，测试校验的还是旧结构。

### dev-comment-discipline

注释纪律。判断标准只有一句：注释里说的东西，在当前代码里还存在吗？不存在就删。不写无信息注释，公共方法只描述自身契约、不绑定业务。`TODO:` 是「有意留白且已登记」，要写清现在是什么、终态是什么、谁收尾、什么时候必须收尾。

### dev-ui-reuse

组件优先。判据不是「哪个库里有」，是「这个需求属于哪一类」：项目已引入的组件库有就用，共享层有就用，都没有才手写，而手写的那个要落进共享层。定制只走组件库给出的入口（主题变量、token、插槽），不改内部结构选择器。

### dev-ui-page-layout

布局默认起点。上中下三段，头尾可选、主体滚动；骨架在公共样式里铺一次，页面只负责用类名。声明了 `scope: always`，任何有界面的项目都适用。

### dev-vue-container-split

容器与业务分离。业务组件和容器是两个文件、同一个目录，对外只有容器一个入口；开关状态与挂载时机归容器，业务按它实际是什么命名，不叫 `Content`、`Body`、`Wrapper`；容器里不写外观样式（teleport 出去，`scoped` 打不到）。只在 Vue 项目里出现。

### dev-vue-sfc-order

单文件组件三段顺序。`template` 在最上、`script` 居中、`style` 在最后；空的段直接省略；`style` 默认 `scoped`，要作用到 teleport 节点时优先搬进全局样式而不是去掉 `scoped`。只在 Vue 项目里出现。

### dev-init-project

项目初始化。唯一一个会往项目里写文件的条款，也是唯一关掉模型自动调用的：只有你手打 `/dev-init-project` 才跑。它是一次性动作，把「每个项目都要有、每次都得重写一遍」的基础件按项目自己的结构放好。

## 三层怎么分

| 层 | 载体 | 放什么 | 缺了会怎样 |
| --- | --- | --- | --- |
| 按需 | `skills/` | 有判断空间的条款 | 没人记得去查 |
| 常驻 | `prompt.md` | 最易违反、一句话能说清 | 记不住细节 |
| 门禁 | `tools.guard` | 二值判定：拦 / 放 | 只会拦，不解释为什么 |

分配判据三条：能不能机械判定、违反代价多大、值不值得每轮占上下文。门禁只有「拦」「放」两态——凡是要「提醒一下」的，做出来一定变成误拦。

## 条款怎么出现

插件不把条款一股脑注册进去。它注册一个 provider，DSH 每次收集 catalog 时会把当前工作目录传进来，插件据此算身份、挑条款：

```
provider.list({ cwd }) ──► 指纹 ──► 可见性 ──► 当前项目的条款清单
```

身份从标记文件推出来，多源任一命中：`package.json` 的依赖、`go.mod`、`pyproject.toml`、`pom.xml`、`.git/config` 里的远端。

- **栈**：`dev-vue-sfc-order` 只在 vue 项目出现。第二个词必须落在栈表里才算栈条款，`dev-git-commit` 的第二个词不在表里，所以它是通用的。
- **仓库**：`metadata.repo` 声明范围。用声明而不是前缀，是因为仓库名常含连字符，前缀在第一个 `-` 处就有歧义。
- **认不出身份 → 全部可见**。藏起来的代价大于多给的代价。

新增条款只要守住命名或写一行声明，可见性自动正确，不改代码。

## 门禁

三类动作进门禁，判据都是二值的：

- **版本控制写操作**：`git commit` / `push` / `reset` / `checkout` / `branch -D` 这类。拦的是 AI 的自动化行为，不是人的操作自由。
- **构建与测试**：`npm run build`、`vite build`、`tsc`、`go test`、`cargo build`、`mvn package`、`./gradlew build`、`make`、`pytest`、`node --test`。`npm run dev`、`npm install`、裸 `vite` 不拦——它们不是构建。
- **敏感路径写入**：`.env`、`*.pem`、`*.key`、`secrets.*`、`credentials.*`；`*.example` / `*.sample` 放行。

只看真正会被执行的片段：按 `&&`、`;`、换行切段，每段开头必须是指令本身，所以 `echo "git commit"` 和 `git log --grep=commit` 都不误拦。异常一律放行。

总开关：环境变量 `DSH_DEV_GUARD=off`，重启生效。

## 草稿区

撤下 ≠ 删除。四条描述团队流程或特定领域的条款被移到这里，内容完整保留：

| 草稿 | 为什么撤下 |
| --- | --- |
| `branch-model.md` | `dev` 集成分支、`release` 冻结、`support`、双合——需要有人并行开发且要保持某个版本可回溯时才成立。 |
| `change-request.md` | 合并请求、关联单号、发布说明聚合——没有 issue 与 PR 流程时无处附着。 |
| `auth-layers.md` | 认证/请求级/展示级三层与数据归属校验——需要服务端鉴权与角色体系。 |
| `permission-granularity.md` | 权限点粒度与中间态——依赖权限表与角色分配。 |

每份都写了状态、来源、缺什么、取回条件。取回走三步：重写 → 建回 `skills/<名字>/` → 跑 `node --test`。

## 结构

| 文件 | 性质 | 干什么 |
| --- | --- | --- |
| `src/kernel.js` | 纯函数 | 命令判定、敏感路径、门禁裁定 |
| `src/fingerprint.js` | 纯函数 + 一次读取 | 从文件快照推导身份 |
| `src/assembly.js` | 纯函数 | 声明范围与身份的求交 |
| `src/catalog.js` | 读目录 | 扫描 `skills/`，解析 frontmatter |
| `index.js` | 唯一有副作用的地方 | 装配：provider + 常驻段 + 门禁 |

规则会频繁改，装配很少改。混在一起的结果是每改一条规则都要跑一遍端到端。

## 测试

```sh
node --test
```

46 个断言，三类：内核（git 与构建两类命令的判定、放行/拒绝用例、坏输入不抛错）、装配（纯函数可见性 + 真实挂载后两个临时项目返回不同条款）、结构（目录名与 name 一致、description 长度与路由判据、引用的补充文件存在、草稿区无生效形态文件、常驻 4–6 条、公共条款无本机地址与内网 IP）。

## 这个版本没做的

- **跨目录的激活状态累积**。`provider.list()` 只拿得到 `cwd`，拿不到会话标识，所以得到的是「当前目录的视角」。
- **门禁只有三类判据**。分支名、提交范围、改动规模这类需要读仓库状态的，都留在技能里靠判断，不做硬拦。
- **仓库事实类条款为空**。机制支持 `metadata.repo`，但还没有真实的仓库条款进来。
