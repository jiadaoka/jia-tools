# 认证与授权的分层

写错权限不会报错——它只会让某些元素悄悄消失，或者悄悄对所有人敞开。所以这一块必须按语义分层，不能凭「加个判断」解决。

## 1 三个概念，别混

| 概念 | 回答的问题 | 在哪校验 | 校验失败的表现 |
| --- | --- | --- | --- |
| **认证** | 你是谁 | 服务端（令牌、会话、签名） | 401 / 跳登录 |
| **请求级授权** | 你能不能调这个操作 | 服务端，操作入口 | 403 / 业务拒绝 |
| **展示级授权** | 你要不要看到这个入口 | 客户端，读下发的标识集合 | 元素不渲染 |

请求级与展示级是**两套**机制，用途不同，**不可互换**：

- 用展示级替代请求级 → 前端隐藏了，但接口没有校验，任何人直接调接口都能成功。**只藏不拦 = 没拦。**
- 用请求级去做展示级 → 客户端拿不到这类标识（服务端不公开），条件恒假，入口对所有角色隐藏，包括最高权限者。

## 2 客户端显隐不是安全边界

- 客户端的一切（隐藏、置灰、路由守卫、本地缓存）都只是**体验**，不是**安全**。
- 敏感操作必须在服务端校验，且校验必须包含**数据归属**，不能只校验「有没有这个操作的权限」。
- 最常见的组合漏洞：列表接口做了过滤，详情接口按 ID 直读、未校验归属。攻击者遍历 ID 即可。

## 3 排查分侧

| 现象 | 大概率在哪 |
| --- | --- |
| 401 / 要求重新登录 | 认证 |
| 403 / 操作被拒绝 | 请求级授权：标识未登记、未分配、归属校验不通过 |
| 入口不显示 | 展示级授权：标识不匹配、类型用错、下发集合里没有 |
| 入口对所有人显示（含无权限者） | 展示级缺失，或判空时默认放行（`has('') === true` 一类） |
| 能点但报错 | 两层都缺：展示级没做、请求级也没做 |

分侧的价值在于：**先判断是哪一层的问题**，再去看代码。混在一起查，最常见的错是「前端觉得后端没下发，后端觉得前端没判断」。

## 4 自检

1. 这个操作的服务端校验做了吗？校验包含数据归属吗？
2. 客户端显隐是否被当成了安全边界？
3. 有没有拿展示级去替代请求级，或者反过来？
4. 判空时默认放行了吗？
